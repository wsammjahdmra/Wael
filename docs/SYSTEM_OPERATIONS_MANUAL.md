## 1. نظرة عامة ومعمارية النظام (System Architecture Overview)

منصة عقار هي منظومة تقنية متكاملة لإدارة ونشر الإعلانات العقارية والوساطة والمشاريع السكنية والتجارية، متوافقة مع متطلبات الهيئة العامة للعقار وهيئة الزكاة والضريبة والجمارك (ZATCA).

### المعمارية التقنية:
1. **الواجهة الأمامية (Frontend):**
   - بيئة React 19 مبنية بواسطة Vite.
   - لغة TypeScript مع تصميم أنيق متجاوب بالكامل باللغة العربية عبر Tailwind CSS.
   - دعم التوجيه المتجاوب والشاشات المكتبية والجوالة وشريط التنقل السفلي.
2. **الخادم وواجهات البرمجة (Backend & API):**
   - خادم Express.js متكامل عبر `server.ts` و `src/server/routes.ts`.
   - محرك مصادقة خادمي يعتمد على التجزئة الآمنة `SHA-256` مع Salt ديناميكي.
   - حماية متقدمة ضد هجمات التخمين (Rate Limiting & Lockout بعد 5 محاولات خاطئة).
   - توثيق مركزي لجميع العمليات الحساسة في سجل التدقيق غير القابل للتعديل (`audit_logs`).
3. **طبقة البيانات (Database Layer):**
   - دعم كامل لقاعدة بيانات **MySQL 8.0+** مع ملفات DDL متكاملة (`database/schema.sql`) وبيانات أولية نموذجية (`database/seed.sql`).
   - محرك بيانات متزامن مدمج فوري للبيئة التطويرية والتجريبية، مع شاشة تحكم تفاعلية في قاعدة البيانات وإمكانية التبديل والمزامنة.

## 2. متطلبات التشغيل والتثبيت (System Prerequisites & Installation)

### المتطلبات الأساسية:
- **Node.js:** الإصدار 18.x أو 20.x أو أحدث.
- **NPM / Bun:** مدير الحزم المعتمد.
- **قاعدة بيانات MySQL (اختياري للتشغيل المحلي المباشر عبر XAMPP / Laragon / Docker):** الإصدار 8.0 فما فوق.

### خطوات التثبيت والتشغيل السريع:
```bash
# 1. تثبيت الاعتماديات
npm install

# 2. بدء تشغيل خادم التطوير والتطبيق
npm run dev

# سيعمل التطبيق على المنفذ المحلي: http://localhost:3000
```

### ملفات التهيئة (`.env`):
```env
PORT=3000
NODE_ENV=development
APP_NAME=منصة عقار
MYSQL_HOST=localhost
MYSQL_PORT=3306
MYSQL_USER=root
MYSQL_PASSWORD=
MYSQL_DATABASE=aqqar_db
AUTH_SECRET_SALT=aqqar_salt_2026_secure
```

## 3. تفعيل قاعدة بيانات MySQL (MySQL Setup & Activation)

لتفعيل قاعدة بيانات MySQL الفعلية:
1. شغل خادم MySQL (عبر XAMPP أو Laragon أو سطر الأوامر).
2. أنشئ قاعدة بيانات باسم `aqqar_db` بترميز `utf8mb4_unicode_ci`:
   ```sql
   CREATE DATABASE IF NOT EXISTS aqqar_db CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
   ```
3. نفّذ ملف المخطط الهيكلي المتوفر في المشروع:
   ```bash
   mysql -u root -p aqqar_db < database/schema.sql
   ```
4. قم بتغذية البيانات التأسيسية:
   ```bash
   mysql -u root -p aqqar_db < database/seed.sql
   ```
5. كما يمكنك استخدام **شاشة إدارة قاعدة البيانات المدمجة في المنصة** عبر الرابط الداخلي: `لوحة التحكم الإدارية -> قاعدة بيانات MySQL المحلية` لفحص الاتصال، وتصدير واستيراد الجداول، وتشغيل استعلامات SQL حية مباشرة من المتصفح!

## 5. مصفوفة الصلاحيات وقواعد التفويض (RBAC Security Matrix)

تعتمد المنصة على نظام صارم ومغلق مبني على مبدأ الامتيازات الأقل (Principle of Least Privilege):

1. **التحقق الخادمي الصارم (Server-Side Enforcement):**
   - لا يتم الوثوق بأي دور مرسل من طرف العميل أو محفوظ في LocalStorage.
   - يتم التحقق من صحة المستخدم ودوره وحالته (نشط / موقوف / معلق) في كل عملية API حساسة.
2. **بوابة الزائر (Visitor Gate):**
   - يسمح للزائر بتصفح العقارات العامة، المشاريع، الخريطة، والمؤشرات السوقية.
   - عند محاولة إجراء تفاعلي (إضافة للمفضلة، نشر إعلان، حفظ بحث، مراسلة معلن)، يتم حجز العملية فوريًا وإظهار نافذة التسجيل/الدخول دون مقاطعة التصفح.
3. **حماية تسجيل الدخول والتخمين (Rate Limiting & Lockout):**
   - يتم احتساب المحاولات الخاطئة في جدول الحسابات.
   - عند وصول 5 محاولات خاطئة متتالية، يتم قفل الحساب تلقائيًا لمدة 15 دقيقة، مع تسجيل محاولة اختراق في سجل التدقيق.
4. **استعادة كلمة المرور (Password Recovery Flow):**
   - يدعم النظام طلب استعادة كلمة المرور عبر الجوال أو البريد المسجل.
   - يتم إنشاء رمز تحقق مؤقت (OTP) صالح لمدة 10 دقائق فقط ويستخدم لمرة واحدة.
   - إبطال رمز التحقق فور إتمام تغيير كلمة المرور لمنع استخدامه ثانية.

## 6. دورة حياة الإعلانات والحالات التسع (Listing Lifecycle & Moderation)

يمر كل إعلان عقاري في المنصة بمسار دورة حياة نظامية تشمل الحالات التالية:
1. `draft` (مسودة): قيد التحرير من قبل المعلن ولم ترسل للمراجعة بعد.
2. `pending_verification` (بانتظار التحقق): تم إرسالها وهي قيد التدقيق وفحص رخصة فال والصك.
3. `published` (منشور): معتمد ونظامي ومعروض في البوابة العامة والبحث.
4. `rejected` (مرفوض): مرفوض من قبل المشرف مع بيان وتوثيق السبب الإلزامي للمعلن.
5. `archived` (مؤرشف): إعلان قديم أو منتهي لم يعد معروضاً للبحث.
6. `pending_payment` (بانتظار السداد): في انتظار سداد باقة الترويج أو رسوم الخدمة.
7. `expired` (منتهي الصلاحية): انتهت مدة النشر المقررة وتتطلب تجديداً من المعلن.
8. `suspended` (موقوف نظامياً): موقوف بقرار إداري أو رقابي لوجود بلاغ أو مخالفة.
9. `deleted` (محذوف منطقياً): محذوف مع الاحتفاظ بسجل البيانات للمراجعة والتدقيق المالي.

## 7. دليل الاستجابة للطوارئ والصيانة (Incident Response & Troubleshooting)

### 1. التعامل مع تجميد الحسابات أو قفل المحاولات:
- يدخل مدير النظام إلى شاشة: `لوحة التحكم الإدارية -> المستخدمون والصلاحيات`.
- يبحث عن رقم جوال أو بريد المستخدم.
- ينقر على خيار "تنشيط وفك القفل"، مما يصفر عداد المحاولات الخاطئة ويزيل تاريخ القفل، ويوثق العملية في سجل التدقيق.

### 2. تدقيق المخالفات عبر سجل التدقيق (Audit Log):
- الدخول إلى: `لوحة التحكم الإدارية -> سجل التدقيق الإداري المحمي`.
- يمكن الفلترة بنوع الحدث (`AUTH_LOGIN_SUCCESS`, `AUTH_LOGIN_FAILED`, `AUTH_ACCOUNT_LOCKED`, `LISTING_APPROVED`, `REFUND_PROCESSED`).
- يحتوي كل سجل على معرّف الفاعل، العنوان البريدي، التوقيت الدقيق، والتفاصيل الكاملة للتغييرات.

### 3. النسخ الاحتياطي لقاعدة البيانات (MySQL Backup):
```bash
# إنشاء نسخة احتياطية كاملة
mysqldump -u root -p --routines --triggers aqqar_db > aqqar_backup_$(date +%Y%m%d).sql

# استعادة النسخة الاحتياطية
mysql -u root -p aqqar_db < aqqar_backup_20260101.sql
```
